BUKTI PENGUJIAN LANGKAH 4 (pengamanan login dan sesi)
Lingkungan uji: PHP 8.3, MariaDB 10.11, Laravel 12.61, data awal dari DatabaseSeeder
Skenario dijalankan otomatis dengan login dan permintaan HTTP sungguhan.

################ SEBELUM PERBAIKAN (versi langkah 3) ################
=== LANGKAH 4: pengamanan login dan sesi
GAGAL  4a login salah beruntun diblokir; password benar pun ditolak selama diblokir  -> 8 percobaan salah=['salah', 'salah', 'salah', 'salah', 'salah', 'salah', 'salah', 'salah']; lalu password benar=masuk
LOLOS  4b setelah batas direset, login dengan password benar berhasil
LOLOS  4c ID sesi berganti setelah login (anti session fixation)  -> berganti
LOLOS  4d cookie sesi berflag HttpOnly dan SameSite  -> HttpOnly=True SameSite=lax Secure=False (Secure baru aktif di HTTPS)
GAGAL  4e GET /logout tidak boleh mengeluarkan pengguna (anti logout paksa lewat link)  -> GET /logout -> 302; sesudahnya /dashboard -> 302
LOLOS  4f logout berhasil dan cookie sesi lama tidak bisa dipakai ulang  -> logout -> 302; /dashboard dengan cookie lama -> 302; /dashboard sesudah -> 302
GAGAL  4g 'Ingat saya' membuat pengguna tetap masuk setelah sesi hilang  -> cookie=['remember_token']; /dashboard tanpa cookie sesi -> 302
LOLOS  4h tanpa 'Ingat saya', sesi yang hilang berarti keluar  -> /dashboard -> 302
GAGAL  4i tombol logout berupa form POST, bukan link  -> form POST=False link GET=True

RINGKASAN: 5 lolos dari 9 skenario
